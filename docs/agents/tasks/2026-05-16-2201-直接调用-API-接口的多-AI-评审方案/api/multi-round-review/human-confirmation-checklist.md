# 人工确认清单

## 必须人工确认的节点

| ID | 节点 | 需要确认什么 | 默认处理 | 状态 |
|---|---|---|---|---|
| HC1 | 输入脱敏 | 输入是否包含密钥、PII、连接串、内网地址、生产配置；是否允许外发给模型。 | 命中敏感信息则禁止外发。 | approved |
| HC2 | 任务拆分 | 子任务边界、DAG 依赖、执行顺序、合并策略是否合理。 | 人工声明任务需要拆分后，再进入拆分流程；未声明或未确认则不拆分。 | approved |
| HC3 | 高风险静态规则 | 是否涉及生产配置、数据库、权限、资金、密钥轮换、隐私数据。 | 命中则阻断，等待批准。 | approved |
| HC4 | DeepSeek 不可用 | 无反方风险审查时是否允许继续。 | 等待 DeepSeek 可用；不生成可执行 final plan。 | approved |
| HC5 | Qwen 不可用 | 无结构化方案输出时是否允许继续。 | 等待 Qwen 可用；不进入后续裁决。 | approved |
| HC6 | 解析失败 | 模型输出无法解析时是否人工修正或重试。 | 默认不合成可执行计划。 | approved |
| HC7 | Pre-flight 失败 | 是修改计划、重试、还是终止。 | 默认进入 rework。 | approved |
| HC8 | 高危 rework 关闭 | 返工是否真的修复，是否需要安全复验。 | 默认需要复验。 | approved |
| HC9 | 验收 P0/P1 | 是否接受剩余 P0/P1 风险。 | 默认不接受，验收失败。 | approved |
| HC10 | Rework 超限 | 超过 3 次返工后，是继续、终止还是拆分。 | 默认停止自动回流。 | approved |
| HC11 | 首次上线 | 首次启用 API-runner 是否由人工全程监督。 | 默认需要监督。 | approved |
| HC12 | 规则更新 | 静态风险规则重大更新后的首次运行是否人工监督。 | 默认需要监督。 | approved |

## 已确认的用户决策

| ID | 决策 | 结论 |
|---|---|---|
| D1 | 真实 API 调用门禁 | 接受双重开关：`MULTI_REVIEW_API_CALLS=enabled` + `--execute`。 |
| D2 | token/cost 限制 | 不设置硬上限；只记录 usage，不因预算阈值阻断调用。 |
| D3 | 自动执行代码或外部分派 | 第一版不允许。 |
| D4 | API 评审结果沉淀 | 默认写入 artifact，聊天只返回摘要。 |
| D5 | 输入脱敏命中 | 禁止外发给外部模型。 |
| D6 | 任务拆分触发 | 只有人工声明后才拆分任务；拆分后仍需确认边界和依赖。 |
| D7 | DeepSeek 或 Qwen 不可用 | 等待对应模型可用，不用缺失模型结果生成可执行 final plan。 |
| D8 | 模型输出解析失败 | 默认不合成可执行计划。 |
| D9 | 其他人工确认项 | 采用表格中的默认处理方式。 |

## 确认记录格式

每条人工确认必须记录：

```json
{
  "id": "HC1",
  "decision": "approved|rejected|not_applicable",
  "owner": "",
  "reason": "",
  "timestamp": "",
  "evidence_refs": []
}
```
