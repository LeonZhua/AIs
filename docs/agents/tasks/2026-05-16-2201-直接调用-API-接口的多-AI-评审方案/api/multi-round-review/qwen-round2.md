# Qwen Round 2 Convergence

## 对 DeepSeek 意见的采纳/反驳

| DeepSeek 核心意见 | 决策 | 收敛依据与工程化处理 |
|:---|:---:|:---|
| **P0 评审输入敏感数据外泄** | ✅ 采纳 | 必须在 API 调用前增加**输入清洗与脱敏门禁**。采用正则+轻量本地模型扫描，命中密钥/PII/生产连接串直接拦截，禁止进入外部模型管道。 |
| **P0 执行可行性黑盒/无沙箱** | ✅ 采纳 | 明确 `final-plan` 到 `acceptance` 之间必须插入**执行沙箱与预检阶段**。验收必须比对“预期行为”与“沙箱执行痕迹”，否则闭环断裂。 |
| **P1 任务拆分无人工确认与集成契约** | ✅ 采纳 | 拆分必须输出带 `dependencies` 与 `merge_strategy` 的 DAG 结构，并强制引入**人工审批门禁**。子任务间需声明集成契约（接口/状态/数据流）。 |
| **P1 验收 Rework 无闭环** | ✅ 采纳 | 采纳状态机回流设计。`rework-items` 触发 `plan-revision` 或 `sub-task-retry`，设置 `max_rework_cycles=3`，超限强制转人工。 |
| **P1 失败降级策略模糊** | ✅ 采纳 | 定义确定性降级矩阵（超时→指数退避重试→降级本地规则校验→人工拦截），禁止自由裁量。 |
| **P2 静态规则人工确认缺协议** | ✅ 采纳 | 绑定确认渠道（CI 门禁/工单系统）、SLA 与责任人，所有确认记录写入 `human-decisions.json` 并附加数字签名。 |
| **P2 Artifact 审计缺防篡改** | ✅ 采纳 | 全链路注入 `trace_id`，所有产物生成 SHA-256 摘要并写入不可变日志链。裁决与验收前必须校验前置产物哈希一致性。 |
| **P2 成本无熔断** | 🔄 修改 | 不采纳“硬阻断”，改为**软熔断+降级策略**：`soft_cost_limit` 触发告警并自动降级为“本地规则+人工确认”，记录降级原因，避免账单失控。 |
| **P3 三模型过度设计** | 🔄 修改 | 拒绝“完全退回单模型”，但**拒绝硬编码三厂商**。改为**角色抽象管道**（Planner/Reviewer/Adjudicator），MVP 阶段支持 `1模型+规则引擎`，生产阶段按需路由多 AI。 |
| **Dry-run 定义模糊** | 🔄 修改 | 明确定义：`dry-run` = 不调用外部 API，仅执行本地 Schema 校验、静态规则扫描与配置语法检查；`--execute` = 启用外部 API 调用与沙箱执行。 |

## 最终方案必须包含

### 🔴 P0 级强制项（阻断实施红线）
1. **输入安全脱敏门禁**：所有进入多 AI 管道的文本/代码/配置必须经过本地脱敏扫描。未脱敏或脱敏置信度 `<0.9` 的任务直接拦截，禁止外发。
2. **执行沙箱与预检机制**：`final-plan` 通过后，必须在隔离沙箱中执行 `pre-flight`（依赖解析、权限模拟、网络连通性探测、配置语法校验）。预检失败直接拦截，不进入真实执行。
3. **验收闭环状态机**：明确定义 `Seed → Breakdown → Review → Pre-flight → Execute → Acceptance → (Rework/Close)` 状态流转。验收报告必须包含 `pass/fail`、`evidence_refs`、`rework_scope`、`next_action`，驱动自动回流或关闭。
4. **Schema-First 契约**：`seed-package`、`task-breakdown`、`adjudication`、`acceptance-report` 等核心产物强制使用 JSON Schema 校验。Markdown 仅作为人类可读附件（由 JSON 渲染生成）。门禁逻辑必须基于 JSON 字段解析。

### 🟠 P1 级强制项（工程化与可靠性）
5. **DAG 任务拆分与合并契约**：拆分阈值量化（如 Token > 5000 或涉及 >3 子系统）。输出必须包含 `execution_order`、`dependencies`、`merge_strategy`（append/overwrite/conflict-resolve）。拆分后需经轻量级无环校验。
6. **确定性降级矩阵**：
   - 超时/空输出：指数退避重试（max 3）→ 失败则标记 `degraded: true`，跳过该 AI 角色，降级为本地静态规则。
   - 解析失败：直接拦截，进入人工替换分支。
   - 连续失败 ≥3 次：任务终止，触发 `incident-alert`。
7. **成本软熔断与路由降级**：设置 `soft_cost_limit` 与 `max_retry_budget`。触发时不阻断，但自动切换至“低成本模型/仅本地规则”模式，并记录审计日志。

### 🟡 P2 级强制项（可观测性与审计）
8. **全链路 Trace 与哈希链**：每个任务分配全局 `trace_id`。所有 artifact 生成后计算 SHA-256 摘要，写入 `calls-log.jsonl`。后续阶段必须校验前置摘要，防止中间篡改。
9. **人工确认协议绑定**：静态风险规则（DB/权限/资金/PII/密钥）触发时，必须生成结构化审批工单，绑定 SLA 与责任人。审批结果写入 `human-decisions.json`，未闭环不得流转。

### 🟢 P3 级优化项（架构弹性）
10. **角色抽象与模型路由**：将 Qwen/DeepSeek/Codex 抽象为 `Planner`、`Reviewer`、`Adjudicator` 角色。支持配置化路由，MVP 阶段可降级为 `单模型 + 规则引擎`，验证有效性后再启用多 AI 对抗。

## 人工确认清单建议

| 触发场景 | 确认内容 | 输出产物 | 阻断条件 |
|:---|:---|:---|:---|
| **任务拆分** | 子任务边界合理性、DAG 无环、集成契约完整性 | `task-breakdown.json` + 人工签名 | 依赖冲突/边界模糊/无集成策略 |
| **静态风险拦截** | 生产配置、数据库变更、权限提升、资金逻辑、PII/密钥暴露 | `human-decisions.json` | 未获授权人审批/SLA 超时 |
| **输入脱敏失败** | 疑似敏感数据是否可安全掩码或替换 | 脱敏报告 + 人工放行/拦截 | 无法脱敏或业务强依赖明文 |
| **成本/重试软熔断** | 是否接受降级执行或暂停任务等待扩容 | 降级决策记录 | 拒绝降级且无备用预算 |
| **高危 Rework 关闭** | 安全边界/资金逻辑修复是否彻底，是否需复验 | `acceptance-report.json` (rework_closed) | 证据不足/未通过安全复验 |
| **首次上线/规则大版本更新** | 全流程端到端走查，确认状态机与降级路径生效 | 上线监督报告 | 任何 P0 门禁未通过 |

## 剩余风险

| 风险域 | 描述 | 缓解策略 |
|:---|:---|:---|
| **模型幻觉与逻辑盲区** | 即使通过 Schema 校验与反方审查，复杂业务边界条件仍可能被遗漏。 | 沙箱执行必须配套自动化集成测试用例；验收阶段强制要求 `evidence_refs` 指向可复现的测试日志。 |
| **沙箱与生产环境差异** | 预检与沙箱无法 100% 模拟生产网络拓扑、第三方服务限流或动态权限。 | 引入灰度发布与流量镜像机制；验收报告必须标注 `env_drift_risk`，高风险项强制人工复核。 |
| **规则库维护成本** | 静态风险规则需持续迭代，否则会成为误报/漏报瓶颈。 | 建立规则版本化管理（GitOps）；配套自动化规则测试集；按季度进行规则有效性审计。 |
| **多 AI 延迟与调试复杂度** | 角色抽象管道在 MVP 阶段可简化，但生产多 AI 路由会增加链路调试难度。 | 全链路结构化日志 + `trace_id` 可视化；提供 `--dry-run --verbose` 模式输出完整决策树，便于离线排查。 |

> **收敛结论**：本方案已吸收 DeepSeek 在安全边界、执行闭环、降级确定性与审计防篡改方面的核心诉求，同时修正了过度依赖 Markdown、硬编码三模型、成本无熔断等工程缺陷。最终架构以**状态机驱动 + Schema-First + 角色抽象管道 + 确定性降级**为骨架，具备明确的 P0/P1 阻断红线与可实施路径。建议按 Phase 1（单模型+强校验+人工门禁）→ Phase 2（多 AI 路由+沙箱预检+软熔断）→ Phase 3（自动化回流+防篡改审计）分步落地。
