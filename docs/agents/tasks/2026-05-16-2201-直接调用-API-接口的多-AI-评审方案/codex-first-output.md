# Codex 第一轮产出物

## 定位

Codex 第一轮产出不是“最终方案”，也不是给外部模型看的笼统 prompt。它是 API 多 AI 评审的本地种子包，作用是把任务边界、评审目标、模型分工、输入材料和裁决规则一次性说清楚。

后续 Qwen 与 DeepSeek 的 API 请求都应基于这个种子包派生，而不是各自收到散乱的自然语言描述。

## 第一轮必须输出什么

Codex 第一轮必须生成 5 个部分：

1. `task_brief`：任务一句话目标和非目标。
2. `constraints`：不可违反的安全、执行、成本和文档边界。
3. `model_assignments`：Qwen、DeepSeek、Codex 各自职责。
4. `review_inputs`：传给外部模型的最小上下文。
5. `adjudication_rules`：Codex 后续如何合成、拒绝或阻断方案。

## 标准结构

```json
{
  "task_brief": {
    "goal": "设计 API-runner 版本的多 AI 评审流程",
    "non_goals": [
      "不实现代码",
      "不修改生产配置",
      "不在输出中包含任何密钥",
      "不继续扩展人工粘贴式 full 流程"
    ]
  },
  "constraints": {
    "security": [
      "API Key 只从本地环境变量读取",
      "不得打印 Authorization header",
      "不得把密钥写入文档、日志、任务记录或对话"
    ],
    "execution": [
      "默认 dry-run",
      "真实调用必须显式 --execute",
      "P0/P1 或高风险未消解时停止自动执行"
    ],
    "scope": [
      "Qwen 负责 API 编排方案",
      "DeepSeek 负责反方风险审查",
      "Codex 负责本地合成与裁决"
    ]
  },
  "model_assignments": {
    "qwen": {
      "role": "API 编排与结构化方案",
      "must_answer": [
        "最小流程",
        "API runner 架构",
        "输入输出结构",
        "错误处理",
        "成本记录",
        "验收标准"
      ]
    },
    "deepseek": {
      "role": "反方风险审查",
      "must_answer": [
        "流程不合理环节",
        "必须保留的安全边界",
        "容易失败的 API 调用场景",
        "成本和人工门禁建议",
        "简化版最终流程"
      ]
    },
    "codex": {
      "role": "本地集成、裁决和最终计划生成",
      "must_do": [
        "过滤敏感信息",
        "校验外部输出是否可用",
        "合并 Qwen 和 DeepSeek 的互补意见",
        "遇到高风险时阻断自动执行"
      ]
    }
  }
}
```

## 给 Qwen 的派生输入

```text
你是 Qwen，职责是 API 编排与结构化方案。

请基于 Codex 第一轮种子包，产出 API-runner 方案。重点回答：
1. 最小流程是什么；
2. API runner 需要哪些组件；
3. 输入输出结构如何定义；
4. 错误处理和成本记录如何做；
5. 如何验收。

硬约束：不得输出任何密钥、token、Authorization header；真实调用必须默认关闭，只能通过显式 --execute 开启。
```

## 给 DeepSeek 的派生输入

```text
你是 DeepSeek，职责是反方风险审查。

请基于 Codex 第一轮种子包和 Qwen 方案，指出：
1. 当前流程哪些环节不合理；
2. 哪些安全边界不能砍；
3. API 调用最容易在哪些场景失败；
4. 成本和人工门禁应该如何约束；
5. 你建议的最简最终流程是什么。

硬约束：不得要求用户提供密钥；不得把模型输出直接视为可执行指令；高风险未消解时必须建议人工确认。
```

## Codex 裁决规则

Codex 合成最终计划时按以下规则处理：

- Qwen 的 API 编排建议优先用于结构设计，但不能覆盖安全边界。
- DeepSeek 的 P0/P1 风险默认阻断自动执行，除非人工明确确认。
- 如果 Qwen 和 DeepSeek 冲突，以更保守、更少副作用、更少外部调用的方案为默认。
- 如果任一模型输出为空、超时或 schema 不合格，不伪造其意见；最终计划必须标记缺失来源。
- 如果方案继续要求多轮交叉评审，默认视为过度设计，除非任务本身涉及高风险生产变更。

## 第一轮输出的验收标准

- 读者无需知道之前的对话，也能理解任务目标和边界。
- Qwen 和 DeepSeek 的输入不是泛泛 prompt，而是从同一份种子包派生。
- 明确 Codex 不是外部评审模型，而是本地集成和裁决者。
- 明确哪些环节应该砍掉：人工粘贴、默认交叉评审、三模型完整 plan 重复生成。
- 明确安全底线：密钥不落盘、不打印、不进文档，真实调用显式开启。
